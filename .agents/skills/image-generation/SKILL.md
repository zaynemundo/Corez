# Image Generation

Use `visual-creative` first when the task is art direction only. Use this skill
when code must call, test, or debug the actual CoreZ image endpoint.

## When to use

- A chat or test flow must actually generate an image via `POST /api/image` or `POST /api/image/cf`.
- A generation request fails or returns 400/429/502/503 and the real cause must be reported.
- Verifying that the returned payload reports the `model` that served the image.
- Debugging `referenceImage` handling or image URL safety (HTTPS or data URL, no private hosts).
- Checking whether generated bytes were persisted to `ASSET_BUCKET`.

## When not to use

- Art direction, palettes, or prompt aesthetics without endpoint code - use `visual-creative`.
- Setting provider key or secret values - use `ask-env-values`.
- General API contract or retry design around the endpoint - use `backend-architecture`.
- Rendered UI around the image component - use `frontend-design`.

## Endpoint contract

- `POST /api/image` is the OpenRouter path and requires `OPENROUTER_API_KEY`.
  Optional `"referenceImage"` (base64 `data:image/...` URL of the user's own
  image or a public https URL) is forwarded to the model as multimodal image
  input, so stylisation and "make it like this" requests use the reference
  instead of inventing from text alone. The worker rejects malformed or
  internal-host references with 400.
- `POST /api/image/cf` is the keyless Workers AI path and requires the `AI`
  binding (no provider key). Body: `{ prompt, width?, height?, seed?, model? }`
  (dimensions 256-1920). Default model `@cf/black-forest-labs/flux-2-klein-4b`
  with `@cf/black-forest-labs/flux-1-schnell` fallback; success also returns
  `{ image, model }`, and 503 without the binding.
- `OPENROUTER_API_KEY` is required. `OPENROUTER_IMAGE_MODEL` may override the
  server-controlled default with one model.
- Success returns `{ image, model }`. Report the returned `model`; do not assume
  a provider or hard-code a legacy model name.
- The returned image must be an HTTPS URL or a valid image data URL. The worker
  rejects loopback, private, link-local, and metadata hosts.
- With `ASSET_BUCKET`, generated bytes are persisted and a CoreZ asset URL is
  returned. Without it, the provider URL may be returned directly.
- Client disconnect is the abort signal. The Worker endpoint must return an
  honest failure rather than a fake generated image. A client may render a
  clearly labelled local placeholder, but must not describe it as provider
  output.

## Prompt workflow

1. Extract the exact subject and requested style, composition, lighting,
   palette, camera perspective, and aspect ratio.
2. Keep factual or explanatory text separate from the image prompt for mixed
   question-and-image requests.
3. Make one endpoint request per requested asset unless the user asks for
   variations.
4. Validate the response shape and image URL before rendering it.
5. Surface 429, 502, and 503 responses honestly, including whether
   configuration, rate limiting, or provider output caused the failure.

## Guardrails

- Do not claim background removal, inpainting, or arbitrary image editing
  beyond what the configured model supports; report the returned `model` and
  keep expectations honest (reference images guide generation — similarity
  depends on the provider model).
- Do not expose provider keys to the browser or accept a client-selected model.
- Do not claim persistence unless the returned URL is the stored CoreZ asset.
