# Interface language (i18n)

The interface ships in **English (default)** and **Arabic**, and Arabic renders
the whole document right-to-left. Everything lives in `src/i18n/`; there is no
translation dependency and no build step.

## How it works

| Piece | Responsibility |
| --- | --- |
| `src/i18n/languages.js` | Supported languages, their direction, the `corez_language` storage key |
| `src/i18n/<lang>/<area>.js` | One dictionary file per screen area, per language |
| `src/i18n/dictionaries.js` | Registry, dotted-key lookup, `{placeholder}` interpolation, English fallback, ambient language for non-React utilities |
| `src/i18n/index.jsx` | `I18nProvider`, `useI18n()`, persistence, `<html lang/dir>` sync |
| `src/rtl.css` | Every right-to-left correction (loaded after `index.css`) |

```jsx
import { useI18n } from "../i18n/index.jsx";

function Example() {
  const { t, language, setLanguage, languages, dir, isRTL } = useI18n();
  return <button>{t("common.sidebar.newChat")}</button>;
}
```

`useI18n()` also works outside the provider and then behaves as English, so a
component can be rendered in isolation (unit tests, previews) without a guard.

## Adding a string

1. Add the English key to the matching `src/i18n/en/<area>.js`, grouped under a
   nesting object that names the screen (`composer`, `billing`, `plans`, …).
2. Use it: `t("chat.composer.placeholder")`. Interpolate with `{name}`:
   `t("chat.attachmentCount", { count })` → `"{count} files attached"`.
3. Add the Arabic value to `src/i18n/ar/<area>.js` with the same key and the same
   `{placeholders}`.

Rules:

- **English wording never changes during a localisation pass.** English strings
  are asserted by the UI tests and are also the fallback for every language.
- Translate text content *and* user-facing attributes (`aria-label`, `title`,
  `placeholder`, `alt`).
- Do not translate user data, code, page names, URLs, currencies, brand names or
  technical tokens.
- Never build a sentence by concatenating fragments — one key per sentence.

## Verification

- `npx vitest run tests/i18n.test.jsx` enforces dictionary integrity: no missing
  key, no unknown key, no English left in the Arabic file, identical
  `{placeholders}` in every language.
- The same file proves the language switch updates `<html lang>`, `<html dir>`
  and `localStorage`, and that the Settings control drives it.
- `tests/i18n-rtl.test.jsx` keeps the right-to-left stylesheet honest: the
  physical rules that `direction: rtl` cannot fix must have an override.

## Adding a language

1. Add the entry to `SUPPORTED_LANGUAGES` in `src/i18n/languages.js`
   (`{ id, label, nativeLabel, dir }`).
2. Create `src/i18n/<id>/<area>.js` for every area in `DICTIONARY_AREAS`
   (start from empty objects — English fills the gaps).
3. Add the language to `DICTIONARIES` in `src/i18n/dictionaries.js` and to the
   pre-paint check in `index.html`.
4. If the language is right-to-left, extend `src/rtl.css`.
