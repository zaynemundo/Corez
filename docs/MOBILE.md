# Corez Mobile (Capacitor)

The native shells live in `android/` (and `ios/` once generated on a Mac) and are
produced by [Capacitor](https://capacitorjs.com) from the same React app in
`src/`. There is no second UI codebase.

## How it runs

`capacitor.config.json` sets:

```json
"server": { "url": "https://corez.pro" }
```

The WebView loads the deployed site rather than the bundled `dist/` copy. This is
deliberate: `corez.pro` authenticates with an `HttpOnly`, `Secure`,
`SameSite=Lax` session cookie, and the Worker only allows CORS for
`corez.pro`, `chat.corez.pro` and `web.corez.pro`. A locally bundled app would
run on `https://localhost`, which is cross-site to `corez.pro` — the cookie
would not be sent and `/api/*` calls would be blocked. Pointing the WebView at
the live origin keeps cookies, CSP and API routing identical to the browser.

Trade-offs of this mode:

- The app needs a network connection; there is no offline shell.
- App Store review (Apple 4.2 "minimum functionality") may treat a pure wrapper
  as too thin. The Play Store is more permissive.

### Moving to a bundled (offline) app

To ship `dist/` inside the binary instead:

1. Remove `server.url` from `capacitor.config.json`.
2. Add the Capacitor origins (`https://localhost`, `capacitor://localhost`) to
   the Worker CORS allow-list in `worker/entry.js` and `worker/customDomains.js`.
3. Replace the cookie session with a header-based token for cross-origin calls
   (or set `SameSite=None; Secure` and add the app origin to the allow-list).
4. Revisit the CSP in the Worker so the app origin is permitted.

## Requirements

| Tool | Version | Notes |
|---|---|---|
| Node | >= 22 | repo engine |
| JDK | 21 | Gradle 8.14 / Android Gradle Plugin |
| Android SDK | platform 36, build-tools 36 | `ANDROID_HOME` or `android/local.properties` |
| Xcode | 15+ | **macOS only** — iOS cannot be built on Windows |

`android/local.properties` is generated by Android Studio and is gitignored.

## Everyday commands

```bash
npm run mobile:sync      # build the web app and copy it + plugins into android/
npm run mobile:assets    # regenerate launcher icons + splash from public/corez.png
npm run mobile:android   # open the project in Android Studio
```

Command-line debug build (no Android Studio needed):

```bash
cd android
./gradlew assembleDebug          # -> android/app/build/outputs/apk/debug/app-debug.apk
```

Install on a connected device:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Branding assets

`scripts/mobile/generate-android-assets.mjs` rewrites every existing
`mipmap-*` launcher PNG and every `drawable*/splash.png` at its current pixel
size from `public/corez.png`, so resource qualifiers stay valid. The adaptive
icon background is `#0A0A0A` (`values/ic_launcher_background.xml`) and the
window background matches, so there is no white flash on cold start.

Re-run it whenever the logo changes:

```bash
npm run mobile:assets && npm run mobile:sync
```

## Release builds

1. Create a keystore:
   `keytool -genkey -v -keystore corez-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias corez`
2. Add `android/keystore.properties` (gitignored):
   ```properties
   storeFile=../corez-release.jks
   storePassword=...
   keyAlias=corez
   keyPassword=...
   ```
3. Wire it into `android/app/build.gradle` `signingConfigs.release` and build:
   `./gradlew bundleRelease` → `android/app/build/outputs/bundle/release/app-release.aab`
4. Bump `versionCode` / `versionName` in `android/app/build.gradle` for every upload.

## iOS

`npx cap add ios` works on any OS, but `cap sync ios`, CocoaPods and
`xcodebuild archive` require macOS with Xcode. The same `capacitor.config.json`
applies; `ios.contentInset: "always"` is already set so the WebView respects the
safe area.
